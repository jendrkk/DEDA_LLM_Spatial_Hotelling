# ADR 019 — Use `find_optimal_rectangle` as Grid Boundary for `build_full_grid`

**Status:** Accepted
**Date:** May 2026
**Deciders:** Jedrzej Slowinski

---

## Context

The `build_full_grid` function in `census.py` constructs the complete
INSPIRE 100 m lattice inside a supplied boundary GeoDataFrame. The natural
choice of boundary is the inner-Ringbahn study area. Two candidates exist:

1. **`select_ringbahn_lor` polygon union** — the union of the selected
   LOR planning districts, which produces an irregular polygon following
   administrative boundaries. Used in the first version of `exe.py`.

2. **`find_optimal_rectangle`** — an axis-aligned rectangular bounding box
   centred on the Ringbahn polygon centroid, sized to the nearest 100 m
   integer multiple, and optimised for maximum population density.
   Used in `GEO_01_lor.ipynb` during interactive development.

The existing `data/processed/pop_grid.parquet` was produced by the notebook
using `find_optimal_rectangle`. The simulation engine consumes `pop_grid.parquet`.

---

## Decision

Use `find_optimal_rectangle` output as the boundary argument for
`build_full_grid` in the production pipeline (`exe.py`).

Parameters (from `GEO_01_lor.ipynb`):
- `rect_buffer_distance = 350.0` m (expand Ringbahn boundary before fitting)
- `rect_augment_layers = (2, 0, 4, 2)` (top, right, bottom, left extra layers)
- `rect_tolerance = 0.01` (1 % density improvement threshold)

---

## Rationale

**Regular lattice structure.** The simulation engine indexes cells by a
regular `(row, col)` grid. An irregular polygon boundary produces cells
at the boundary that are either clipped to partial 100 m squares or
absent from expected lattice positions, breaking the index assumptions.
A rectangular boundary guarantees every expected lattice position is
populated and the INSPIRE grid alignment is preserved end-to-end.

**Alignment with existing data.** `pop_grid.parquet` was generated by
the notebook approach. Switching the pipeline back to the LOR polygon union
would produce a different grid and invalidate the already-computed downstream
artefacts (`gebaeude_stadtstruktur.parquet`, `grid_with_stations.parquet`,
`grid_malls.parquet`, `supermarkets.parquet`).

**Population-density optimisation.** `find_optimal_rectangle` maximises
population density within the rectangle (residents/m²), which concentrates
grid cells on inhabited areas and minimises empty cells at the periphery.
The augmentation layers `(2, 0, 4, 2)` add a small southern and western
margin to ensure no inhabited cells near the boundary are cut off.

**LOR polygons remain useful.** `select_ringbahn_lor` is still called in
Phase 3 of the pipeline to (a) scope the study area for reporting and (b)
provide `PLR_ID`/`PLR_NAME` attributes joined to grid cells in `add_lor_attributes`.
It is no longer used as the grid generation boundary.

---

## Consequences

- `exe.py`: Phase 4 uses `find_optimal_rectangle` instead of `select_ringbahn_lor`
  as the boundary argument to `build_full_grid`.
- `run_default_data_pipeline` gains three new parameters: `rect_buffer_distance`,
  `rect_augment_layers`, `rect_tolerance` to allow tuning without code changes.
- `docs/spatial-module-reference.md` updated to document the rectangular boundary
  and the three new parameters.
- LOR polygon selection (Phase 3) is retained for attribute joining and scoping
  but is decoupled from grid construction.
- Grid cells at the rectangular boundary corners may fall outside the LOR selection;
  these will have `PLR_ID = NaN` after `add_lor_attributes` — acceptable, as they
  correspond to low-population peripheral cells.
